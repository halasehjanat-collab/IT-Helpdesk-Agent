## Supplied VPN escalation transcript (2026-10-30)

The user supplied a demo conversation beginning with a generic VPN failure, followed by `NX403`, `escalate date`, a work email/department claim, and further escalation attempts. The live failure was not merely that required information was missing:

- The error-code index only recognized hyphenated codes, so `NX403` did not pin the KB-002 NX-403 row. Retrieval could include the general VPN article while generation confused NX-403 with the nearby NX-781 version guidance. KB-002 defines NX-403 as Access denied and supports approving the NakhlaKey prompt within 60 seconds, checking NakhlaKey enrollment, and (for new/transferred staff) the VPN-Users group.
- The retrieval query used only the latest short message, losing the prior VPN symptom and code on follow-up turns.
- A work email typed into an ordinary chat message was not resolved against the employee directory; only the separate `user.email` field was checked.
- Ticket intent recognized `escalate this/it` but not a bare `escalate` or the observed `escalate date`, so those turns went back to free-form answer generation and never entered the approval-gated draft path.
- The ticket context helper retained only the immediately previous user turn. Once the short escalation command was recognized, this would have discarded the VPN report and error code.

Fixes are narrow and source/policy-backed: error codes with or without a hyphen are canonicalized before precedence lookup; recent user context is included in retrieval; email supplied in the chat text is directory-verified; bare escalation commands start intake and carry recent issue context; NX-403's KB-002 P2 rule is applied to the resulting ticket; the ticket subject includes the normalized error code. The directory is authoritative: `tariq.hamdan@nakhla.example` is Engineering in the project data, so the user's text claim of Finance does not activate Finance's KB-016 exception. No ticket is written until the exact draft is explicitly approved.

Regression coverage replays the supplied flow, checks NX403 retrieval/generator evidence, checks typed-email directory lookup, confirms the Finance claim does not override the directory, and verifies the approval gate.
